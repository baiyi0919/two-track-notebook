## 1. 核心目标

探索轨支持"多人讨论"模式：同一条线索下，多个角色（"我"的不同视角 + AI角色）参与讨论，模拟团队协作/多角色辩论的场景。

---

## 2. 角色体系（通用，不区分模式）

角色分为两类，**通用**，既可在单人模式使用，也可在多人模式使用。

| 类型 | 说明 | 能否被用户操控发言 |
|------|------|----------------------|
| `human` | "我"的不同视角（如：理性我、感性我、批判性我） | ✅ 可以 |
| `ai` | AI角色（如：产品经理、技术架构） | ❌ 不可以（只能手动触发或自动接力）|

### 默认角色

每个用户自动有一个 `human` 类型角色：**"我"**（id=0，不可删除）。

### 角色属性

| 字段 | 必填 | 说明 |
|------|------|------|
| 名称 | ✅ | 如"产品经理"、"理性我" |
| 头像 | ❌ | Emoji，不填则用名称首字母 |
| 类型 | ✅ | `human` / `ai` |
| 人格设定 | ❌ | 描述角色的说话风格、立场、专业背景 |
| AI配置 | ❌ | 仅`ai`类型需要：model、apiKey、apiUrl |

---

## 3. 两种模式对比

| 特性 | 单人模式 | 多人模式 |
|------|----------|----------|
| 角色栏显示 | 只显示 `human` 角色 | 显示所有角色（`human` + `ai`）|
| 用户操控 | 切换 `human` 角色发言 | 只能切换 `human` 角色发言（多人模式下 `human` 角色只有"我"一个）|
| AI角色发言 | ❌ 无 | ✅ 手动触发（点击AI角色头像）|
| 自动接力 | ❌ | ⏸️ 预留（先不做）|
| 适用场景 | 个人思考、自我辩论 | 模拟团队讨论、多角色协作 |

## 4. 角色管理

### 4.1 角色配置弹窗的打开方式

**两种方式打开角色配置弹窗：**

1. **长按角色栏中的头像** → 打开该角色的配置弹窗
2. **长按消息列表中某条消息的头像** → 打开该消息对应角色的配置弹窗

**添加新角色：**
- 点击角色栏的 **"+"按钮** → 打开空白配置弹窗，填写后创建新角色
- **模式决定默认类型**：单人模式下点击"+"默认创建 `human` 角色；多人模式下点击"+"默认创建 `ai` 角色（用户也可以在弹窗中手动切换类型）

### 4.2 角色CRUD

| 操作 | 触发方式 | 说明 |
|------|----------|------|
| 创建 | 点击"+"按钮 | 打开空白配置弹窗，模式决定默认类型 |
| 编辑 | 长按角色栏头像 或 长按消息头像 | 打开该角色的配置弹窗 |
| 删除 | 配置弹窗内提供"删除"按钮 | 默认"我"(id=0)不可删除 |
| 默认角色 | 自动创建 | 每个用户自动有一个"我"（human类型，不可删除）|

### 4.3 配置弹窗字段

```
[角色名称] *（必填）
[头像 Emoji]（选填，如：🎯 🔧 🧠）
[类型]（human / ai，模式决定默认类型，可手动切换）
[人格设定]（选填，描述说话风格、立场、专业背景）
---
（仅 ai 类型显示以下字段）
[AI 模型]（选择：gpt-3.5-turbo / gpt-4 / claude / deepseek 等）
[API Key]（密码框）
[API 地址]（选填，默认 OpenAI 格式）
---
[保存]  [删除]（仅编辑时显示删除按钮）
```

## 5. 单人模式

- 用户一人操作，通过**切换视角**模拟不同角色发言
- **底部角色选择器**：点击切换当前发言角色（只显示 `human` 角色）
- 发送消息时，记录当前选中的角色（`persona_id` 或 `roleName`）
- 消息列表显示每个发言者的头像、名称、颜色

### UI示意

```
[议题标题]                    [模式切换：单人 / 多人]

消息列表：
  [我 🟣] 我觉得这个方案可行...
  [理性我 🔵] 从数据来看...
  [批判性我 🟢] 但这个方案忽略了...

[底部] [👤 我 ▼] [输入框...] [发送]
```

## 6. 多人模式

### 6.1 角色栏（顶部）

- 顶部横向滚动角色栏，显示**所有**已配置角色（`human` + `ai`）
- 每个角色显示：头像（圆形，带颜色）、名称
- **当前发言角色**高亮（边框/背景高亮）—— 仅 `human` 角色可设为当前发言角色
- **点击 `human` 角色卡片** → 切换为当前发言角色
- **长按任意角色卡片** → 打开该角色的配置弹窗
- **点击 `ai` 角色头像** → 手动触发该AI角色发言
- **点击"+"按钮** → 创建新角色（多人模式下默认创建 `ai` 类型）

### 6.2 消息列表

- 每条消息显示：头像、名称、颜色、内容
- **长按消息头像** → 打开该角色的配置弹窗
- 消息按时间顺序排列
- **AI角色的消息**：右上角显示"AI"标签

### 6.3 发言流程

1. 用户点击角色栏中的某个 `human` 角色 → 切换为当前发言角色
2. 用户在输入框输入消息，点击**发送**
3. 消息以当前发言角色的身份发送
4. **AI角色手动触发**：点击某个 `ai` 角色的头像 → 调用该角色的AI配置生成回复并插入消息列表

### 6.4 AI自动接力（⏸️ 预留，先不做）

**需求描述（预留）：
- 在发送按钮左边有一个**"自动对话"**按钮
- 点击后可设置对话轮次（如：5轮、10轮）
- 轮次结束后自动停下
- **自动发言时谁来说**：根据人格模式让AI自行决定谁来说
  - 问题：这意味着每个AI都要读取一遍当前内容才能决定接下来谁说
  - 缺点：响应慢、token消耗大、涉及算法
  - **结论：先预留，先不做，先手动触发就行**

**预留接口/UI位置：**
- 发送按钮左侧预留"自动对话"按钮位置（可以先隐藏或disable）
- 后端预留自动接力API（暂不实现）

### 6.5 消息显示

- 每条消息显示发言角色的头像、名称、颜色
- **AI角色的消息**：右上角显示"AI"标签（已确认）

## 7. 分析框架（⏸️ 定时更新）

### 7.1 功能描述

每个角色（尤其是AI角色）有一个"分析框架"——即该角色的思维模式、分析问题的框架。

**更新策略：**
- 让AI在**每天固定时间**（如凌晨2:00）自动更新分析框架
- 如果当时没打开该网页 → 等用户**最近一次登录后**进行更新
- 更新时：**提醒用户先不要对话**，平时先暂且不动
- **目的**：确保响应稳定和快速，不然角色的回答会很不稳定，而且还要不停的更新自己的思维框架

### 7.2 数据库设计（`analysis_framework` 表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| persona_id | BIGINT | 关联角色ID |
| content | TEXT | 分析框架内容（AI生成）|
| last_updated | DATETIME | 最近一次更新时间 |
| next_update_time | DATETIME | 下次更新时间 |

### 7.3 更新流程

1. **定时任务**（后端Scheduler）：
   - 每天固定时间（如凌晨2:00）检查 `next_update_time`
   - 如果到达更新时间 → 调用AI API生成/更新该角色的分析框架
2. **登录时检查**：
   - 用户登录后，检查是否有待更新的分析框架
   - 如果有 → **在页面顶部显示提醒条**（不是弹窗）："有X个角色的分析框架需要更新，是否现在更新？"
   - 用户点击"立即更新" → 逐个更新，更新时**在页面顶部显示提醒条**："更新中，请暂且不要对话"
   - 用户点击"稍后" → 关闭提醒条，**推迟到下次登录再提醒**
3. **手动触发**：
   - 在角色配置弹窗中提供"立即更新分析框架"按钮（待确认）

### 7.4 提醒UI设计（页面顶部提醒条）

```
┌─────────────────────────────────────┐
│ ⚠️ 有3个角色的分析框架需要更新。 [立即更新] [稍后] │
└─────────────────────────────────────┘
```

- 位置：页面顶部（fixed，top: 0）
- 样式：黄色/橙色背景，黑色文字
- 按钮：[立即更新] [稍后]
- 更新中：显示进度条 + "更新中，请暂且不要对话"

## 8. 数据库设计（已实施）

### 8.1 `persona_config` 表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| user_id | BIGINT | 所属用户（外键 → `user.id`）|
| name | VARCHAR(100) | 角色名称 |
| avatar | VARCHAR(10) | 头像Emoji |
| type | VARCHAR(20) | 角色类型（`human` / `ai`）|
| model | VARCHAR(100) | AI模型名称（AI角色用）|
| api_key | VARCHAR(500) | API密钥（需加密存储）|
| api_url | VARCHAR(500) | API地址（兼容OpenAI格式）|
| personality | TEXT | 人格设定 |
| is_deleted | TINYINT(1) | 软删除 |
| created_at / updated_at | DATETIME | 时间戳 |

### 8.2 `analysis_framework` 表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| persona_id | BIGINT | 关联角色ID（外键 → `persona_config.id`）|
| content | TEXT | 分析框架内容 |
| last_updated | DATETIME | 最近一次更新时间 |
| next_update_time | DATETIME | 下次更新时间 |

### 8.3 `message` 表新增字段

| 字段 | 类型 | 说明 |
|------|------|------|
| persona_id | BIGINT | 发言角色ID（NULL表示用户本人/旧数据）|

**兼容旧数据**：`persona_id` 为NULL时，读取 `roleName` 字段显示角色名称。

## 9. 后端API（已实施）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/persona-configs/mine` | GET | 获取当前用户的角色列表 |
| `/persona-configs` | POST | 创建角色 |
| `/persona-configs/{id}` | PUT | 更新角色 |
| `/persona-configs/{id}` | DELETE | 删除角色 |
| `/analysis-frameworks?personaId=` | GET | 获取角色的分析框架 |
| `/analysis-frameworks` | POST | 保存/更新分析框架 |
| `/analysis-frameworks/next-update-time` | PUT | 更新下次更新时间 |
| `/messages` | POST | 发送消息（支持 `personaId` 字段）|
