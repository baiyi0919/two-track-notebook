## 1. 核心目标

探索轨支持**多角色讨论**：同一条线索下，多个角色（"我"的不同视角 + AI角色）共同参与讨论，模拟团队协作/多角色辩论的场景。

**关键变更（v5）：**
- ❌ **取消"单人模式 / 多人模式"切换**
- ✅ 所有角色（个人多视角 + AI）**共享同一个讨论空间**
- ✅ 用户可以**切换"个人多视角角色"** 来发言
- ✅ **AI角色** 不能被用户切换，但可以**点击头像手动触发发言**
- ✅ 所有角色的消息显示在**同一个消息列表**中

---

## 2. 角色体系（通用，不区分模式）

角色分为两类，**通用**，所有角色都在同一个讨论空间中。

| 类型 | 说明 | 能否被用户操控发言 | 能否手动触发发言 |
|------|------|----------------------|----------------------|
| `human` | "我"的不同视角（如：理性我、感性我、批判性我） | ✅ 可以（切换后发言） | ❌ 不需要 |
| `ai` | AI角色（如：产品经理、技术架构） | ❌ 不可以 | ✅ 可以（点击头像触发） |

### 2.1 默认角色

每个用户自动有一个 `human` 类型角色：**"我"**（id=0，不可删除）。

### 2.2 角色属性

| 字段 | 必填 | 说明 |
|------|------|------|
| 名称 | ✅ | 如"产品经理"、"理性我" |
| 头像 | ❌ | Emoji，不填则用名称首字母 |
| 类型 | ✅ | `human` / `ai` |
| 人格设定 | ❌ | 描述角色的说话风格、立场、专业背景 |
| AI配置 | ❌ | 仅`ai`类型需要：model、apiKey、apiUrl |

## 3. 讨论空间设计（v5 核心变更）

### 3.1 无模式切换

- **取消"单人模式 / 多人模式"切换按钮**
- 所有角色（human + ai）**共享同一个讨论空间**
- 消息列表显示所有角色的消息（按时间顺序）

### 3.2 角色栏（顶部）

- 顶部横向滚动角色栏，显示**所有**已配置角色（`human` + `ai`）
- 每个角色显示：头像（圆形，带颜色）、名称
- **当前发言角色**高亮（边框/背景高亮）—— 仅 `human` 角色可设为当前发言角色
- **"+"按钮**：右侧添加 **"设置"按钮**（齿轮图标 ⚙️）

**交互规则：**

| 操作 | 目标角色类型 | 行为 |
|----------|----------|----------|
| **点击角色卡片** | `human` | 切换为当前发言角色 |
| **点击角色卡片** | `ai` | ❌ 无反应（或提示"AI角色不能切换"） |
| **点击角色头像** | `human` | 切换为当前发言角色（同卡片点击） |
| **点击角色头像** | `ai` | ✅ 手动触发该AI角色发言 |
| **点击"+"按钮** | - | 打开空白配置弹窗（默认创建 `human` 角色） |
| **点击"设置"按钮** | - | 打开角色配置窗口，默认显示AI角色最靠前的一个 |

**注意（v5.1 重要变更）：**

### 3.3 消息列表

- 每条消息显示：头像、名称、颜色、内容
- **长按消息头像** → 打开该角色的配置弹窗
- 消息按时间顺序排列
- **AI角色的消息**：右上角显示"AI"标签（已确认）

### 3.4 发言流程

1. 用户点击角色栏中的某个 `human` 角色 → 切换为当前发言角色
2. 用户在输入框输入消息，点击**发送**
3. 消息以当前发言角色的身份发送
4. **AI角色手动触发**：点击某个 `ai` 角色的头像 → 调用该角色的AI配置生成回复并插入消息列表

### 3.5 消息显示

- 每条消息显示发言角色的头像、名称、颜色
- **AI角色的消息**：右上角显示"AI"标签（已确认）

## 5. AI角色发言机制

### 5.1 手动触发（已实现）

- 点击AI角色头像 → 调用该角色的AI配置生成回复
- 生成后插入消息列表
- 显示"AI角色名 正在回复..."提示

### 5.2 自动接力（⏸️ 预留，先不做）

**需求描述（预留）：**
- 在发送按钮左边有一个**"自动对话"**按钮
- 点击后可设置对话轮次（如：5轮、10轮）
- 轮次结束后自动停下
- **自动发言时谁来说**：根据人格模式让AI自行决定谁来说
  - 问题：这意味着每个AI都要读取一遍当前内容才能决定接下来谁说
  - 缺点：响应慢、token消耗大、涉及算法
  - **结论：先预留，先不做，先手动触发就行**

**预留接口/UI位置：**
- 发送按钮左侧预留"自动对话"按钮位置（可以先隐藏或disable）
- 后端预留自动接力API（暂不实现）

## 6. 分析框架（⏸️ 定时更新）

### 6.1 功能描述

每个角色（尤其是AI角色）有一个"分析框架"——即该角色的思维模式、分析问题的框架。

**更新策略：**
- 让AI在**每天固定时间**（如凌晨2:00）自动更新分析框架
- 如果当时没打开该网页 → 等用户**最近一次登录后**进行更新
- 更新时：**提醒用户先不要对话**，平时先暂且不动
- **目的**：确保响应稳定和快速，不然角色的回答会很不稳定，而且还要不停的更新自己的思维框架

### 6.2 数据库设计（`analysis_framework` 表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| persona_id | BIGINT | 关联角色ID |
| content | TEXT | 分析框架内容（AI生成）|
| last_updated | DATETIME | 最近一次更新时间 |
| next_update_time | DATETIME | 下次更新时间 |

### 6.3 更新流程

1. **定时任务**（后端Scheduler）：
   - 每天固定时间（如凌晨2:00）检查 `next_update_time`
   - 如果到达更新时间 → 调用AI API生成/更新该角色的分析框架
2. **登录时检查**：
   - 用户登录后，检查是否有待更新的分析框架
   - 如果有 → **在页面顶部显示提醒条**（不是弹窗）："有X个角色的分析框架需要更新，是否现在更新？"
   - 用户点击"立即更新" → 逐个更新，更新时**在页面顶部显示提醒条**："更新中，请暂且不要对话"
   - 用户点击"稍后" → 关闭提醒条，**推迟到下次登录再提醒**
3. **手动触发**：
   - 在角色配置弹窗中提供"立即更新分析框架"按钮（待确认）

### 6.4 提醒UI设计（页面顶部提醒条）

```
┌─────────────────────────────────────┐
│ ⚠️ 有3个角色的分析框架需要更新。 [立即更新] [稍后] │
└─────────────────────────────────────┘
```

- 位置：页面顶部（fixed，top: 0）
- 样式：黄色/橙色背景，黑色文字
- 按钮：[立即更新] [稍后]
- 更新中：显示进度条 + "更新中，请暂且不要对话"

## 13. 踩坑记录（v5.1 新增）

### 13.1 长按事件在 H5 环境下不可靠

**问题描述：**
- 多次尝试使用长按（`@longpress`）打开角色配置弹窗
- 在 H5 环境下，长按事件要么不触发，要么触发了但弹窗没打开
- 尝试了 `uni.showActionSheet` 作为中间步骤，但在 H5 环境下也可能不弹出
- 这个问题卡了好几次，每次以为修复了，结果测试还是不行

**根本原因：**
- H5 环境（浏览器）对长按事件的的支持不一致
- `uni.showActionSheet` 在 H5 环境下可能不显示（依赖原生能力）
- 用户反馈：能看到长按振动反馈，但没有对应的配置窗口打开

**解决方案（v5.1）：**
- ❌ **放弃长按打开配置弹窗**
- ✅ **改为点击"设置"按钮（⚙️）打开配置窗口**
- 在"+"按钮右边添加"设置"按钮
- 点击设置按钮直接打开角色配置窗口，默认显示AI角色最靠前的一个
- 在配置页面添加角色切换器（下拉或列表），选择不同角色时下方表单自动更新

**经验总结：**
- 不要在 H5 环境下依赖长按事件做核心交互
- 如果必须使用长按，一定要提供备用方案（如按钮点击）
- 这次应该一开始就听用户的，直接做个按钮，而不是在长按上浪费时间
